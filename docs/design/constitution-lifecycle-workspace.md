# Constitution lifecycle workspace

The lifecycle editor uses the shared full-width PageChrome toolbar and editorial visual system. **Record event** and **History** are keyboard tabs. **Context** toggles the current legal status and recent history; the preference survives reload. Both event scopes and all history evidence forms stay mounted during navigation, filtering and pane changes so that unfinished document uploads, optional metadata, event notes and provision selections remain intact.

Choose the whole constitution or exact provisions first. Provision selection searches labels, parent paths and wording from a published source snapshot. A parent never implies its children. A version change with selected units needs confirmation; cancellation or failed loading preserves the selection and other fields. The read endpoint checks the user’s Publisher/Admin role, constitution ownership and published version membership before loading content.

The existing Catalog contracts determine event sequencing and dates. Review shows the precise scope, source version, units, event/date, note and pinned documents before submitting. Dates are required; whole-constitution dates may be approximate. Entirely unknown dates remain unrecorded. Current status excludes future events, which remain visible in history. Existing events retain their legal dates and types; evidence revisions and scoped document materials use their existing independent commands and permissions. Older source URLs remain visible and survive note edits.

Both composers reuse `StagedDocumentPicker` and the canonical `DocumentAttachmentTemplate`, documented in [the document attachment skill](../../.agents/skills/verfassung-document-attachments/SKILL.md) and [integration guide](document-attachment-template.md). Optional metadata uses the template’s native disclosures; it is editable and preserved, not omitted. Selections save with the event; library uploads use the existing document-service route. Publisher relationship rights do not grant library creation. `StagedRecordForm` retains failures and its operation receipt for safe retries after an event succeeds but its document pins fail.

The separate interactive mock uses simulated callbacks and explicitly activates disclosures when its inline preview host cancels native click defaults. The application uses the canonical native disclosure behavior. No mock callback, sample document or simulated save enters the application.

Verification covers current/future projections, exact nested unit paths, version boundaries, retained drafts, optional metadata, keyboard tabs/disclosures, review/back/save, failure/retry, publisher permissions, responsive English/German rendering and accessibility. Visual baselines must be captured in the repository’s pinned Playwright Linux image.
