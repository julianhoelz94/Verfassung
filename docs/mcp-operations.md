# MCP and public API access

The MCP endpoint `/mcp` requires a personal `ca_mcp_` key with `mcp:read` for every protocol request. A signed-in user creates and revokes keys under **Account → Connect a chat client**. Import tools additionally require `ingestion:import` and an editor or admin role. No MCP tool approves or publishes a staged item. `/mcp/ping` is a health check and returns no protocol data.

The Caddy edge limits anonymous `GET` and `HEAD` requests to the public Catalog, Content, Amendment, and Search APIs. Each peer IP receives a 120-request burst, refilled at two requests per second. Caddy supplies the peer IP; client-supplied forwarding headers do not control the bucket. The gateway checks the `ca_session` cookie or Bearer credential with Identity `/me` before exempting a request. Expired or invalid credentials use the anonymous bucket. Direct API clients receive `429` and `Retry-After`; a browser visiting an API URL receives a small page with the retry time, public browsing link, and optional sign-in link. Normal site pages remain available without signing in.

The quota is held in the single gateway process used by Compose and resets on restart. Before running multiple gateway replicas, move the bucket to a shared store so the limit stays consistent. If Identity is unavailable, the edge applies the anonymous quota rather than treating an unverified credential as authenticated. Investigate repeated 429s by peer IP and time window without logging cookies, Bearer values, or imported constitution text.

Country, constitution, version, and unit list tools return `nextCursor` for the next page while retaining `nextOffset` for older clients. Cursors are signed, scoped to the collection, and expire after 15 minutes. The collection lists reject a stale cursor when their published membership changes, so clients can restart traversal. Set the same `MCP_CURSOR_SECRET` on every MCP replica to keep cursors valid across replicas and restarts; without one, a random process secret invalidates outstanding cursors on restart.

An importer can call `get_import_upload` to find missing chunks after a disconnect. `cancel_import_upload` removes chunks from a receiving upload and frees its reserved batch bytes. Cancellation is idempotent for the owner; a completed upload has already staged an item and cannot be canceled through this endpoint. A canceled idempotency key remains bound to that canceled upload, so a fresh upload requires a new key. Review and publication remain separate site actions.
