# MCP and public API access

The MCP endpoint `/mcp` requires an account-bound Bearer credential with `mcp:read` for every protocol request. Clients can use browser OAuth authorization with PKCE S256 or a manually created `ca_mcp_` key from **Account → Connect a chat client**. OAuth discovery starts at `/.well-known/oauth-protected-resource/mcp`, which points to the authorization server metadata at `/.well-known/oauth-authorization-server`. The authorization server supports public-client dynamic registration at `/oauth/register`, consent at `/oauth/authorize`, token exchange at `/oauth/token`, and revocation at `/oauth/revoke`. Registration permits 20 requests per peer IP per hour; expired codes and tokens and inactive clients are purged. The consent screen shows the client ID and redirect origin, and Account shows the registered destinations. Revoking a client also invalidates its outstanding codes. OAuth access tokens are audience-bound to the exact public `/mcp` URL, expire after 15 minutes, and are checked against Identity on every request. Register redirect URIs using HTTPS or loopback HTTP; exact matching and PKCE are mandatory. Import tools additionally require `ingestion:import`, an editor or admin role, and fresh MFA confirmation through the consent screen. No MCP tool approves or publishes a staged item. `/mcp/ping` is a health check and returns no protocol data.

The Caddy edge limits anonymous API requests across Catalog, Content, Amendment, Audit, Search, Ingestion, Document, Identity, and Editor. Each peer IP receives a 600-request burst, refilled at ten requests per second. Caddy supplies the peer IP; client-supplied forwarding headers do not control the bucket. The gateway checks the `ca_session` cookie or Bearer credential with Identity `/me` before exempting a request. Expired or invalid credentials use the anonymous bucket. Direct API clients receive `429` and `Retry-After`; a browser visiting an API URL receives a small page with the retry time, public browsing link, and optional sign-in link. Normal site pages remain available without signing in.

The quota is held in the single gateway process used by Compose and resets on restart. Before running multiple gateway replicas, move the bucket to a shared store so the limit stays consistent. If Identity is unavailable, the edge applies the anonymous quota rather than treating an unverified credential as authenticated. Investigate repeated 429s by peer IP and time window without logging cookies, Bearer values, or imported constitution text.

Country, constitution, version, unit, and search tools return `nextCursor` for the next page while retaining `nextOffset` for older clients. Cursors are signed, scoped to the collection or search filters, and expire after 15 minutes. Lists reject a stale cursor when their published membership changes; search rejects one after a committed reindex, so clients can restart traversal. Set the same `MCP_CURSOR_SECRET` on every MCP replica to keep cursors valid across replicas and restarts; without one, a random process secret invalidates outstanding cursors on restart.

Tool failures set `isError` and return a structured `{ code, status, message, retryable }` result alongside readable text. `invalid_cursor` means the client should restart that list from its first page; `unauthenticated` and `forbidden` require an account key with the proper scope. Only retry when `retryable` is true, and preserve the same import idempotency key when retrying a write.

An importer can call `get_import_upload` to find missing chunks after a disconnect. `cancel_import_upload` removes chunks from a receiving upload and frees its reserved batch bytes. Cancellation is idempotent for the owner; a completed upload has already staged an item and cannot be canceled through this endpoint. A canceled idempotency key remains bound to that canceled upload, so a fresh upload requires a new key. Review and publication remain separate site actions.

The server currently uses the durable ingestion job and upload handles as its asynchronous fallback. It does not advertise the MCP Tasks extension until the TypeScript receiver can serve the 2026 `tasks/get` and `tasks/cancel` methods end to end. Clients should poll `get_import_upload`, `get_import_batch`, or `get_import_job`; each call rechecks key scope and ownership. Do not treat a staged import as published when polling reports `pending_review`.

## Capacity and recovery

The MCP transport accepts at most 5 MiB per request and at most 32 concurrent authenticated requests, with at most eight from one account. Saturation returns 429 with `Retry-After: 1`; anonymous/invalid credentials use the separate 120/minute MCP challenge bucket and the edge quota. Direct staging is limited to 2 MiB; larger items use the bounded chunked upload flow. An internal only `/internal/metrics` endpoint exposes active requests and per-tool call/duration buckets; Caddy does not route this endpoint. JSON tool logs include tool, actor ID, resource ID when available, outcome, status and elapsed milliseconds, without tokens or constitution text. Correlate a failed upload by its returned upload, batch, item, or job ID with ingestion audit records.

Run `cd services/mcp-server && npm run load:scenario` after changes to browsing or transport code. It exercises 400 concurrent MCP page reads across a synthetic 5,000-constitution collection with eight clients. The application-layer budget is zero errors, p95 below 2 seconds, and at least 10 requests/second on a development machine; record the measured JSON result. On 2026-10-11 the local run returned zero errors, 203 requests/second, p50 38 ms, p95 45 ms, and p99 76 ms. This isolates MCP serialization and pagination from database and network latency. For a deployed load check, use a dedicated test account/key, request published list and search tools at the same eight-client concurrency, and watch MCP metrics plus Catalog/Search latency; stop when the 429 concurrency signal appears. Do not include staging writes in a load run against production.

Treat client names, uploaded legal text, source URLs, and search snippets as untrusted data. Consent displays the registered redirect origin and client ID; redirect URIs must be exact registered HTTPS or loopback HTTP addresses. An MCP key or OAuth token is an account credential, so keep it out of URLs, logs, issue attachments, and client transcripts. Never use MCP to publish. A suspected credential leak is handled from Account by revoking the key or OAuth connection, then inspecting tool logs and ingestion jobs for that actor. A failed chunked upload can be resumed with `get_import_upload` and its missing chunk indexes; cancel the unfinished upload to release the reservation. A staged item with an error remains private until an authorized editor corrects it, a reviewer/admin approves it, and a publisher/admin releases it through the site with fresh MFA. Approval and publication remain separate actions; the same account can perform them if it has both permissions. If Identity is unavailable, MCP returns 503; restore Identity before retrying with the same idempotency key. On 429, honor `Retry-After` and reduce concurrency.

Protocol compatibility is verified by the repository's MCP SDK contract tests, raw HTTP OAuth browser journey, and full stack staged import journey. On 2026-10-11, the official Inspector 2.10.1 discovered the tools and called `list_countries` through the local stack, and Claude Code reported the same MCP server connected. Both used temporary viewer keys that were revoked immediately afterward. The current server advertises the 2026-07-28 MCP protocol and plain tool polling, without MCP Tasks. A client that does not support OAuth can use a personal key in an Authorization header. Repeat the Inspector and production client connection checks after deployment using the published OAuth discovery URLs.
